Script review

结构弛豫 + MP 凸包稳定性

relaxation_n_ehull.py 用 UMA 优化晶体并预测能量，再把该能量放进 Materials Project 相图，估算 energy above hull。

脚本在做什么

指定 GPU 1，加载 UMA omat 模型
FIRE 联合优化晶胞/原子，再用 BFGS 精修原子
取得弛豫后 UMA 总能量并除以原子数
拉取/缓存同化学体系的 MP entries，建立凸包

主程序只是以金刚石 Si 为测试样例，并输出初始/优化 CIF、轨迹、优化日志与 Ehull。

核心计算
Ehull = EentryUMA+correction − Ehull surfaceMP 单位：eV/atom；代码由 pd.get_e_above_hull(...) 完成
EUMA优化结构的 UMA 势能 / 原子数。传入前先乘回总原子数，构成 ComputedEntry。
correction依据伪势、GGA/GGA+U 与 Hubbard U 元数据，尝试施加 MP2020 compatibility 修正。
EMP不是某一个 MP 材料的能量，而是相同总体组成在 MP 凸包上的最低能量；它常由若干稳定相按比例线性组合得到。
物理含义0 表示落在凸包；正值表示相对最佳分解产物高出的能量，越大通常越偏亚稳。

代码中的真实路径

energy_per_atom × N → raw UMA entry → MaterialsProject2020Compatibility → corrected entry → 与 MP entries 比较。

最重要的前提
两侧必须处在可比的能量标尺上。填写 MP 的 U 值与 POTCAR 名称，只是给修正规则提供元数据，不会自动把 UMA/OMat24 的绝对能量校准为 MP DFT 能量。

因此，这个结果适合作为快速筛选指标；若未验证 UMA 与 MP 的元素参考能、DFT 设置和修正体系一致，不能直接视为严格的 MP-compatible Ehull。

需要警惕的实现细节

  • _COMPAT.process_entry(raw_entry) or raw_entry：若 compatibility 拒绝 entry，代码会静默退回未修正能量，使不同样本处理口径不一致；应记录/报错。
  • allow_negative=False 不应被理解成“解决负值”。若 UMA entry 明显低于 MP 凸包，pymatgen 可能按版本/容差报错或不保留负值；负值本身更可能提示能量标尺失配。
  • 脚本把 MP API key 明文写在源码里，建议立即撤销并改从环境变量 MP_API_KEY 读取。
一句话：算法形式是“候选相能量 − 同组成 MP 凸包能量”，可信度取决于 UMA 与 MP 的能量校准，而不只取决于公式本身。
